Core Web Vitals: the three numbers worth fixing first

22 Sep 20263 min readTechnical SEO · Performance

Google measures page experience with three metrics. Fix these in order of how much they hurt real visitors, and ignore the rest of the noise in speed reports until they are green.

Read the full note

LCP (loading). How fast the biggest thing on screen appears. Usually a hero image or a big heading. Compress it, serve a right-sized version, and don't lazy-load the top image.

INP (responsiveness). How quickly the page reacts when someone taps or clicks. Long JavaScript tasks are the usual cause, so ship less script.

CLS (stability). Whether things jump around while loading. Give images and embeds explicit width and height, and reserve space for anything that loads late.

Measure with field data (Search Console's Core Web Vitals report or PageSpeed Insights), not only lab scores, because Google judges what real users experience.

Takeaway: Fix LCP first. It is the one visitors notice most and the easiest to move.

ON-PAGE SEO

Title tags: still the strongest on-page lever

10 Sep 20262 min read

One line of HTML decides how you look in search results and tells Google what the page is about. Most sites still get it wrong.

Read the full note
  • Put the main keyword near the start, then the brand at the end.
  • Keep it around 50–60 characters so it isn't cut off on results pages.
  • Every page needs its own title. Duplicates confuse both Google and people.
  • Write for a human first. Google may rewrite titles that look stuffed or vague.

Takeaway: If two pages could share a title, one of them probably shouldn't exist.

ON-PAGE SEO

Meta descriptions don't rank, but they still earn clicks

28 Aug 20262 min read

Not a ranking factor, yet a better description can be the difference between a scroll-past and a click.

Read the full note

Treat the description as ad copy for the page: one clear promise, the keyword used naturally, and a reason to click. Around 120–160 characters is a safe range.

Google often replaces your description with a passage from the page that matches the search. That's normal, so make sure the page itself answers the query clearly.

Takeaway: Write it for the person deciding whether to click, not for the crawler.

TECHNICAL SEO

Canonical, 301 or noindex: which one to use

14 Aug 20263 min read

Three tools that look similar and solve three different problems. Mixing them up is one of the most common technical mistakes.

Read the full note
  • 301 redirect: the old page is gone for good and users should land on the new one.
  • Canonical: both URLs must stay live (filters, tracking parameters), but one is the main version.
  • noindex: the page should work for visitors but stay out of search (thank-you pages, internal search).

Don't block a page in robots.txt and also expect a noindex on it to work. Google can't see the tag on a page it isn't allowed to crawl.

Takeaway: Gone = 301. Duplicate = canonical. Private = noindex.

LOCAL SEO

Local SEO for a small business: the boring basics that work

30 Jul 20263 min read

Nearby customers find you through a handful of unglamorous things done consistently.

Read the full note
  • Claim and fully complete the Google Business Profile: category, hours, services, photos.
  • Keep name, address and phone identical everywhere they appear.
  • Give each real location or service area its own useful page, not copy-pasted city swaps.
  • Ask happy customers for reviews and reply to every one.

Takeaway: Consistency beats cleverness. Same details, everywhere, always.

TECHNICAL SEO

Schema markup: only mark up what people can see

12 Jul 20262 min read

Structured data helps search engines understand a page. It can also get you in trouble if it doesn't match reality.

Read the full note

Use JSON-LD and make sure every claim in it is also visible on the page. Test with Google's Rich Results Test and the Schema Markup Validator.

Also keep expectations honest: since 2023 Google shows FAQ rich results only for a small set of well-known government and health sites. FAQ markup is harmless elsewhere, but don't expect the expanded snippet. Person, Organization, Breadcrumb and Article markup are still worth having.

Takeaway: Schema describes the page. It doesn't decorate it with things that aren't there.

WEB DEV

Don't hide your content behind JavaScript animations

25 Jun 20262 min read

A scroll-reveal that starts at opacity 0 looks great, until the script fails and the page is blank.

Read the full note

I learned this on my own portfolio: my reveal animation hid every section by default, so with JavaScript off the content stayed invisible. Google can render JavaScript, but visitors with a failed script or a slow connection can't.

  • Make the content visible by default and let JS enhance it.
  • Add a <noscript> fallback if something must start hidden.
  • Respect prefers-reduced-motion.

Takeaway: Animation is a bonus. The content has to work without it.

WORDPRESS · SHOPIFY

WordPress and Shopify: five settings I check before anything else

8 Jun 20263 min read

Before touching keywords, I check that the platform isn't quietly working against the site.

Read the full note
  • WordPress: "Discourage search engines" is unticked in Settings → Reading (it often stays on after launch).
  • WordPress: permalinks use readable post names, not ?p=123.
  • Shopify: product URLs under collections have a canonical pointing to the main product URL.
  • Shopify: product and collection pages have unique titles, descriptions and image alt text.
  • Both: the XML sitemap is submitted in Google Search Console.

Takeaway: Ten minutes of settings checks can undo months of "invisible" problems.

PERFORMANCE

Images: the fastest speed win on most sites

20 May 20262 min read

On most pages I audit, images are the biggest download. Fixing them moves LCP more than anything else.

Read the full note
  • Use modern formats like WebP or AVIF where supported.
  • Resize to the size actually displayed. Don't ship a 4000px photo into a 600px slot.
  • Set width and height to prevent layout shift.
  • Lazy-load images below the fold, but never the main hero image.
  • Write alt text that describes the image, for accessibility first and SEO second.

Takeaway: Compress first, then optimize code. Images usually decide the score.
